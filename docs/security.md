# 安全、隐私与公开版本

## 公开源码包含什么

公开版本仅包含应用源码、通用配置模板、测试、虚构示例与静态介绍页。默认没有真实日历、服务、入口、设备或外部数据源；首次初始化必须自己设置密码，会话密钥随机生成。

不包含作者线上配置、数据库、服务器 / NAS 地址、私人域名、真实姓名、课程记录、订阅链接、GitHub Token、设备凭证、日志、备份或真实面板截图。GitHub 仓库作者名和仓库 / Pages 链接属于公开项目标识，予以保留。

运行配置通过 `.gitignore` 排除；提交前运行 `python scripts/check_public.py`。检查器只提供有限的静态检查，不是完整 DLP 或密钥扫描产品；仍需人工检查待提交差异。

更新采用替换当前源码树的提交，保留已有 Git 提交历史。此说明只描述当前公开版本，不代表对历史提交做了清除或隐私保证。若历史曾泄露密钥，应先撤销 / 轮换，再单独处理历史。

## 应用保护与限制

- 所有个人指标 / 日程 / 配置读取均需登录。会话签名、HttpOnly / SameSite Cookie、修改接口的 CSRF Token、登录节流用于降低常见风险。
- 密码使用 PBKDF2-HMAC-SHA256；生产 HTTPS 与 Secure Cookie 不能关闭。
- Agent 使用独立随机 Token，服务器只保存其哈希。Token 只能上报自身节点，不能读取课表或其他节点；可以撤销。
- API 依赖一层可信代理；反向代理须覆盖转发头，API 不应直接暴露在公网。
- ICS / 新闻下载做响应大小、超时、重定向及公网地址校验，逐跳固定 DNS 解析地址；不允许请求内网或链路本地地址。
- 私人日历路径、查询参数和可选 GitHub Token 仅放服务端运行配置，配置文件权限为 0600。备份也应加密或限制访问。
- 指标采集会包含主机名、IP、进程名、网卡与系统信息。账户应由本人保管，不应把登录后的面板做公开分享或将数据库上传仓库。
- SQLite 数据明文保存在服务器磁盘，应用没有数据库级加密；应使用主机访问控制、磁盘保护与可靠备份。

当前没有多因素认证、复杂权限模型、操作审计平台、邮件 / 短信推送、跨地区探测或 SLA。源码中的保护不等于经过独立安全审计。

## 生产建议

使用长随机密码、有效 TLS、专用系统用户和最小权限 Token；保持依赖更新。避免让管理后台和个人课表依赖公开可猜的路径来代替鉴权。

默认探测来自本机服务器，不能替代独立的外部可用性监测。资源采集权限不足时允许显示未知，不能为拿到更多指标而随意放宽整机权限。

## 报告问题

可以通过仓库 Issues 提交不含敏感值的复现步骤。不要把可利用的攻击载荷、个人凭证或线上配置直接贴到公开 Issue；先脱敏，必要时先请求维护者提供合适的私密联系渠道。
